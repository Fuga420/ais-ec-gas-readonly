## Part 1: 下書き商品の英語タイトル単独編集対応 (`update_product` translated_title対応・本番v94デプロイ)

### 1. 目的とスコープ
- **目的**:
  1. Readdy 管理画面の下書き商品一覧プレビュー画面から「表示中の英語タイトル（`translated_title`）」を単独でインライン編集・保存可能にする。
  2. `update_product` が下書き商品の `translated_title` を単独の変更項目として受け取り、`product_translations` シートの該当商品英語タイトルへ安全に保存する。
  3. 空欄は受け付けず（`TRANSLATED_TITLE_REQUIRED`）、前後の空白を除去（トリム）して保存する。
  4. 既存翻訳レコードの説明文・状態・箱・付属品・承認ステータス（`approved` 等）は完全に維持し、タイトル編集だけで他が空にならないようにする。本票の日本語商品名（`product_name`）や販売予定価格（`planned_sale_price`）も変更しない。
  5. 一覧API（`GET ?mode=admin`）および詳細API（`GET ?mode=admin&product_id=...`）が、保存直後に新タイトルを返すよう、商品別翻訳キャッシュ（`prod_trans_<productId>`）を即座に破棄する。
  6. `update_product` の既存の部分更新、価格変更時のSquare処理、公開・在庫処理には変更を広げない。タイトルだけを送った場合に価格が変わらないことを確認する。
- **担当境界**: GASバックエンド（`コード.js`, `tests.js`, `test_harness_standalone.js`）、GAS Web App デプロイ管理、実機API結合検証。

### 2. 設計および実装内容
- `updateProductTranslatedTitle_(productId, newTitle)`（`コード.js` L1235〜L1329）:
  - `product_id` と `translated_title` の必須検証。空文字・空白のみの場合は `TRANSLATED_TITLE_REQUIRED` をスロー。
  - `product_translations` シートを末尾逆順走査し、最新の `locale: "en"` レコードを検索。
  - 既存行がある場合: `translated_title` 列（および `generated_at` 列）のみ上書き更新。説明文・状態・箱・付属品・ステータスは完全維持。
  - 既存行がない場合: ヘッダー列構造に合わせた新規レコードを追加（`locale: "en"`, `translation_status: "approved"`）。
  - `CacheService.getScriptCache().remove("prod_trans_" + normId)` で詳細取得用キャッシュを即時クリア。
- `handleUpdateProduct(sheet, data)`:
  - `data.translated_title` が指定された場合、`currentPublishStatus !== "draft"` であれば `TRANSLATED_TITLE_DRAFT_ONLY` をスロー（下書き限定）。
  - 空白のみは `TRANSLATED_TITLE_REQUIRED` で拒絶。
  - `data.product_name` や `data.planned_sale_price` が含まれていなければ、本票（Sheets[0]）の更新やSquare同期処理は一切スキップ。

### 3. デプロイおよび実機検証結果
- **GASデプロイ**: 固定Web AppデプロイID `AKfycbyxee-…` を **v94** へ更新。

## Part 2: 同時送信時の事前検証順序安全化 (`update_product` 事前検証・本番v95デプロイ)

### 4. 目的とスコープ
- **目的**:
  1. `update_product` に `translated_title` と `planned_sale_price` を同時送信した際、価格が不正であればタイトルも変更されないよう、書き込み前の検証順序を修正する。
  2. 入力値事前検証フェーズ（Pre-Validation Phase）と書き込み・外部同期フェーズ（Execution / Write Phase）を厳格に分離する。
  3. 不正な価格（負数、非数値、小数等）が送信された場合、`product_translations` への英語タイトル保存やSquare同期を行わずに即座に例外で停止（Fail-closed）し、既存のタイトル・価格を100%保持する。
  4. 正常な同時更新では、タイトルと価格の双方が安全に保存・更新されることを確認する。
  5. 既存の Square 価格処理（パターンB: 旧Link無効化 -> Square価格更新 -> BIS価格更新 -> 新Link生成）を完全維持する。

### 5. 設計および実装内容
- `handleUpdateProduct`（`コード.js` L1350〜L1510）:
  - **フェーズ1（入力値の事前検証 / Pre-Validation）**:
    - `translated_title`: 下書き限定チェック、空文字・空白のみのチェック（`TRANSLATED_TITLE_REQUIRED`）。
    - `category`: 作成後変更禁止チェック。
    - `planned_sale_price`: `!Number.isSafeInteger(newPrice) || newPrice <= 0` の正の整数チェック。不正時は `Error("planned_sale_price must be a positive integer")` を即座にスロー。
    - `pokemon_card`: オブジェクト構造の妥当性検証。
    - **※この段階ではシート書き込み・Square API呼び出し・キャッシュクリアを一切行わない**。
  - **フェーズ2（書き込み・外部同期 / Execution Phase）**:
    - すべての検証を通過した後にのみ実行。
    - `translated_title` の保存（`updateProductTranslatedTitle_`）およびキャッシュクリア。
    - `pokemon_card` の保存。
    - `planned_sale_price` の Square 同期（既存のパターンB処理を完全維持）。
    - 本票（Sheets[0]）のセル書き込み。
