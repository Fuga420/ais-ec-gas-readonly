## 2. 価格条件の「概算原価への最低30％上乗せ（`min_cost_markup_rate`）」への変更と GAS v103 本番反映

### (1) 変更内容
1. **価格下限条件の変更（`概算原価 × 1.30` を価格単位で切り上げ）**:
   - [`llm_product_draft.js`](../../llm_product_draft.js) の `AI_DRAFT_CONFIG.DEFAULT_MIN_COST_MARKUP_RATE` を `0.30`（概算原価への最低30％上乗せ、倍率 `1.30`）に設定。
   - 下限価格 $P_{\text{floor}} = \text{ceilPriceByPolicy\_}(\text{概算原価} \times (1 + \text{min\_cost\_markup\_rate}))$（10,000円以上は100円単位、1,000〜9,999円は50円単位、1,000円未満は10円単位で切り上げ）を算出。
   - Web相場提案 $P_{\text{market}} \ge P_{\text{floor}}$ なら相場価格を採用（`price_decision_source: "market_above_cost_markup_floor"`）、$P_{\text{market}} < P_{\text{floor}}$ なら原価上乗せ下限価格を採用（`price_basis: "cost_markup_floor"`, `price_decision_source: "cost_markup_floor"`）。
2. **既存の `min_gross_margin_rate`（粗利率）と混同しない API 項目名・価格根拠への統一**:
   - API リクエスト/レスポンス項目名を **`min_cost_markup_rate`**（別名 `min_markup_rate`、既定 `0.30`）および `cost_markup_multiplier`（既定 `1.3`）、`pricing_rule: "cost_markup_floor"` に統一。
   - 未更新の Edge Function 等が `min_gross_margin_rate: 0.2` を自動付与してきても、`min_cost_markup_rate` の計算に流用せず既定の `0.30`（30％上乗せ）を適用する安全分離を実装。また不正な `min_gross_margin_rate`（`<= 0` または `>= 1`）が明示指定された場合は `INVALID_MIN_GROSS_MARGIN_RATE` で拒否。
   - `price_note` の文言を「確定税込原価（または参考配賦原価）への最低30%上乗せ（×1.30）による下限価格（○○円）」「原価比+○○%」に刷新し、粗利率（分母＝販売価格）と混同しない表記に統一。
