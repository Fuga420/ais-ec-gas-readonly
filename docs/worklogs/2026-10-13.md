### 3. 設計および実装内容
1. **POSTルーターへの `attach_product_document` 組み込み**:
   - `doPost(e)` に `data.action === "attach_product_document"` のルーティングを追加。
2. **入力パラメータの柔軟性対応**:
   - フロント側の命名差異（snake_case / camelCase / 代替名）を全網羅して安全に受け入れ:
     - `product_id` / `productId`
     - `idempotency_key` / `idempotencyKey` / `document_attempt_id`
     - `document_type` / `documentType` (`receipt` または `invoice`)
     - `file_name` / `fileName` / `original_file_name` / `filename`
     - `mime_type` / `mimeType` / `mime`
     - `base64` / `base64_data` / `base64Data` / `data`
3. **MIME種別検査とマジックバイト推定**:
   - 許可形式: PDF (`application/pdf`), JPEG (`image/jpeg`), PNG (`image/png`)。
   - `image/jpg`, `image/pjpeg` を `image/jpeg` へ正規化、`application/x-pdf` を `application/pdf` へ正規化。
   - MIME省略時または `application/octet-stream` 時に、Base64先頭マジックバイト（`JVBERi` -> PDF, `iVBORw0KGgo` -> PNG, `/9j/` -> JPEG）または拡張子から安全に自動判定。
4. **書類容量（サイズ上限）検査**:
   - `MAX_FILE_SIZE_BYTES: 15MB` (15 * 1024 * 1024) を設定。
   - 超過時は `error_code: "DOCUMENT_SIZE_EXCEEDED"` を返却。
5. **レスポンス契約の統一**:
   - フロントが期待する `success: true` と `document` オブジェクト（`product_id`, `file_id`, `document_type`, `original_file_name`, `mime_type`, `file_size`, `created_at`, `view_url`, `open_url`）を返却。後方互換性のためフラットなトップレベルフィールドも同時に提供。
   - 同一キー・同一内容の再送時は `is_reused: true` で既存レコードを安全に返却（二重作成ゼロ）。
   - 異なる内容の同一キー再送・同一商品への別書類添付は `DOCUMENT_ALREADY_EXISTS` 競合エラーを返却。
6. **管理画面表示と公開商品ページからの完全隔離**:
   - 管理画面（`mode=admin`）での商品詳細API（`buildProductDetail`）および専用API（`doGet?action=get_product_document`）に `product.document`（`open_url` 含む）を付与。
   - 一般公開商品ページ（`mode` なし / `isAdmin === false`）では `product.document` プロパティ自体を完全除外。
   - 商品フォルダ内専用サブフォルダ `documents/` 格納および登録 `file_id` の除外フィルタにより、商品画像一覧・サムネイル・AIドラフト推論・画像指紋・Square/eBay連携への混入を物理的に完全遮断。

### 9. 工程2 追加レビュー指摘（再紐付け・行番号再利用・NULL金額区別）の反映と結合テスト

#### ① 指摘事項と対応方針
1. **紐付け解除後の再紐付け（UNIQUE制約 `(document_line_id, product_id, link_type)` 衝突回避）**:
   - PostgreSQLのUNIQUE制約は論理削除済み（`is_deleted = true`）レコードも一意性の対象とするため、unlink後に同じ商品・同じlink_typeへの再紐付け時に制約違反が発生する問題。
   - **対応**: DDLスキーマ変更（部分一意インデックス等）を行わず、Edge Function（`link_product_manual`）側で既存レコードを検索し、削除済みリンクが存在する場合は新規INSERTせず、`is_deleted = false, status = 'confirmed', confirmed_by, confirmed_at, allocated_amount, notes, updated_at = NOW()` に更新して再利用・復元する最小実装を採用。
2. **明細削除後の同じ行番号での再登録（UNIQUE制約 `(document_id, page_number, line_number)` 衝突回避）**:
   - 論理削除後も同じ書類・ページ・行番号での再登録が `(document_id, page_number, line_number)` のUNIQUE制約に衝突する問題。
   - **対応**: Edge Function（`save_document_lines`）側で、同一書類・ページ・行番号のレコードが存在する場合は削除済みであっても新規INSERTせず、`is_deleted = false, is_active = true, deleted_at = NULL, deleted_by = NULL, updated_at = NOW()` で再活性化し全フィールドを上書き更新する最小実装を採用。
3. **金額未入力 (NULL) と 0円 (0.00) の厳格な区別**:
   - `Number(item.total_line_amount) || 0` による0補正を廃止。未指定・空文字は `NULL`、明示的な数値（0を含む）のみ `Number()` 変換して保存するよう統一。`item_amount`、`tax_amount`、`fee_amount`、`allocated_amount` も同様の扱いに揃え、未確定明細と0円明細の区別を保持。
4. **結合テストの拡充**:
   - 単体テストに加え、WASM PostgreSQL隔離環境による Edge Function ロジック結合テストに Test 8（unlink後の同商品再紐付けと原価再集計）、Test 9-1/9-2（明細論理削除と同ページ・行番号再登録）、Test 10（NULL vs 0.00 保持検証）を追加。
