## Part 1: AIドラフト自動反映条件の緩和・SKU誤読値排除・本番Web App v92デプロイおよび一括生成実測

### 1. 目的とスコープ
- **目的**:
  1. `identity_status === "confident"` を本票ドラフトへの自動反映の必須条件から外す。
  2. サイズ・箱ラベル・SKUが未確認でも、生成された商品名、説明、カテゴリ、ブランドなどの有用な値を商品ドラフト（本票）へ反映する。正の整数の価格案があり販売予定価格が未入力なら、H列へ直接反映する。スタッフ入力済みの値は保持する。
  3. 不明なサイズは空欄で構わない。要確認項目（`needs_review`）はドラフトレコードに残すが、要確認があることを理由に他の生成値の反映を止めない。
  4. `FACING-THE` や `LABEL-SIDE` や `BENEATH-THE` のようなプロンプト指示語・画像構図語句由来の明らかな誤読値をSKUに入れない。
  5. 2段階検索グラウンディング通信・外部検索時間を考慮し、単品実行TTL（`EXECUTION_TTL_MS`）を 90秒から 240秒（4分）へ拡張する。
  6. 一括処理において、反映したドラフト値を再読取して判定し、サイズ未確認だけで失敗にせず商品名等が実際に入った商品は成功（`completed`）として表示する。
  7. 今回失敗した商品のいずれか（`TMP-000120`）で通常の一括生成から商品詳細画面まで確認し、商品名・説明・価格の反映とバッチ成功を実測する。公開やSquare連携は実行しない。
- **担当境界**: GASバックエンド（`llm_product_draft.js`, `tests.js`, `test_harness_standalone.js`）、GAS Web App デプロイ管理。
- **非対応スコープ**: 公開処理（`assertProductPublishable_` による公開ゲート検証）、Square 連携、商品一覧・詳細のフロントエンド修正。

### 2. 直近バッチ失敗の原因究明結果
1. **`identity_status === "confident"` による本票反映ブロック**:
   - `executeSingleAiProductDraftCore_`（L5106-5110）において `if (candidate.identity_status !== "confident") shouldAutoApply = false;` となっており、箱ラベル・サイズ未確認の画像では `candidate` または `ambiguous` に判定され、本票への `applyCandidateToProduct_` がスキップされていた。
   - しかしバッチワーカー（`processAiBatchQueue` L7227）はスキップされたケースを考慮せず無条件に `verifyProductDraftReflectionCompleted_`（本票完全性検証）を実行していた。
   - 本票の商品名が空欄 `""` のままであったため、`PRODUCT_NAME_NOT_REFLECTED` 例外がスローされ、ドラフト候補の生成自体は成功（Dunk Rainbow 4,400円等）しているのにバッチが失敗扱いにされていた。
2. **プロンプト指示語・構図語句のSKU誤読**:
   - 箱ラベル未撮影時、Geminiが画像からラベル文字を読もうとするがラベルが写っていないため、プロンプト指示文（"facing the camera", "label side", "beneath the..." 等）を返し、`normalizeSneakerSku_` のハイフン・スペース結合ロジックによって `"FACING-THE"`, `"LABEL-SIDE"`, `"BENEATH-THE"` がSKUとして抽出されていた。
3. **2段階検索グラウンディング所要時間と実行ロックTTL**:
   - `AI_DRAFT_CONFIG.EXECUTION_TTL_MS` が旧来の90秒のままであったため、外部Web検索を含む2段階推論（60〜100秒）でTTLを超過し `STALE_EXECUTION_DISCARDED` が発生していた。
4. **固定Web AppデプロイID（v91）とGAS HEADの乖離**:
   - 固定デプロイID `AKfycbyxee-…` が過去の配信版 `@91`（v91）のまま固定されており、HEADの修正がWeb App API経由で反映されていなかった。

### 3. 設計および実装内容

#### ① 自動反映条件の緩和 (`executeSingleAiProductDraftCore_`)
- `candidate.identity_status !== "confident"` による `shouldAutoApply = false` を削除。
- サイズ・箱ラベル・SKUが未確認（`candidate` / `ambiguous` 等）であっても、生成された商品名、説明、カテゴリ、ブランドなどの有用な値を商品ドラフト本票（Sheets[0]）へ下書き反映。
- 正の整数の価格案があり販売予定価格が未入力なら、H列へ直接下書き反映。スタッフ入力済み価格は上書きせず保護。
- サイズ未確認時は空欄のまま保持し、要確認項目（`needs_review`）はドラフトレコード側に保持。

#### ② SKU誤読値排除ロジックの強化 (`normalizeSneakerSku_`)
- 無効値正規表現にプロンプト指示語・構図語句（`facing[\s_-]?the`, `label[\s_-]?side`, `camera`, `facing`, `shoe[\s_-]?box`, `angle`, `view`, `photo` 等）を追加。
- 抽出結果の厳格検証を追加:
  - スニーカーのスタイルコード・型番は必ず数字を少なくとも1文字以上含む（`!/\d/.test(result)` は空文字返却）。英字のみの単語ペア（`FACING-THE`, `LABEL-SIDE`, `BENEATH-THE`, `SHOE-BOX` 等）を物理的に完全排除。
  - 指示語・構図語句（`FACING`, `LABEL`, `SIDE`, `CAMERA`, `PHOTO`, `IMAGE`, `PICTURE`, `FRONT`, `BACK`, `ANGLE`, `SHOE`, `BOX` 等）を含む場合は空文字返却。

#### ③ 実行ロックTTLの拡張 (`EXECUTION_TTL_MS`)
- `AI_DRAFT_CONFIG.EXECUTION_TTL_MS` を 90,000ms（90秒）から 240,000ms（240秒 / 4分）へ拡張。バッチワーカーの `MAX_EXECUTION_TIME_MS: 240000` / `LEASE_TTL_MS: 300000` と整合性を確保。
