## 2. 主な実装内容

### 2.1. カテゴリおよび属性の設計
- 主カテゴリに `apparel`（アパレル）と `fashion_goods`（ファッション小物）を追加。
- 既存の `sneaker`, `jewelry`, `pokemon_card`, `other` を完全維持。
- **Chrome Hearts（クロムハーツ）の扱い**: ブランド名（`brand`）として管理し、ジュエリー/アパレル/小物へ適切に分類。
- **Google Sheets 本票の列配置**:
  - 既存の 1〜40列（スニーカー専用 12〜17列、ジュエリー専用 18〜29列、状態・Square・AIフラグ列 32〜40列）は一切変更せずずらさない。
  - 41列目 (AO): `apparel_fashion_subcategory`（サブカテゴリ）
  - 42列目 (AP): `apparel_fashion_size`（サイズ: S/M/Lや36等の文字列）
  - 43列目 (AQ): `apparel_fashion_sku`（公式品番）

### 2.2. `コード.js` の改修
- `executeProductCreationCore_`: 新規登録時に 41〜43列目へ属性を保存。インポート指紋（`computeImportPayloadFingerprint_`）にも属性を追加。
- `handleUpdateProduct`:
  - `fieldMap` に `subcategory` / `sub_category` (41), `size` (42), `official_sku` / `sku` (43) を追加。
  - 登録後のカテゴリ変更禁止チェックを厳格に維持。
  - `currentCategory !== "sneaker"` 時のスニーカー列書き込み遮断、`currentCategory !== "jewelry"` 時のジュエリー列書き込み遮断ガードを導入。
- `buildProductDetail` / `buildAdminProductSummary` / `buildProductSummary`:
  - 新カテゴリ属性（`subcategory`, `size`, `official_sku`）および互換キー（`sub_category`, `sku`）の返却に対応。
- `getSquareProductSourceData_` & `buildSquareProductDisplay_`:
  - 43列目まで読み込み、新カテゴリ用に `buildSquareApparelFashionDisplay_` をディスパッチ。
  - `size` がある場合は Square Catalog の Variation 名にサイズを反映、未指定時は `"Regular"` を設定。
  - 商品説明文 HTML に【サイズ】【品番】【ブランド】を自動掲載。
  - Square 側のカテゴリ ID については実機マッピングが存在しないため推測 ID を入れず、現状のカテゴリ未指定動作を維持。

### 2.3. `llm_product_draft.js` の保護
- `applyCandidateToProduct_`:
  - 既存商品への反映時、既存カテゴリが存在する場合は上書きせず保護。
  - スニーカー列（12列目 `sneaker_sku`, 13列目 `sneaker_size`）の書き込みを、スニーカー以外のカテゴリ（`pokemon_card`, `jewelry`, `apparel`, `fashion_goods`, `other`）では遮断。
- `handleConfirmAiProductDraft`:
  - 既存商品カテゴリの上書きを防止。
  - スニーカー以外のカテゴリ商品へのスニーカー属性誤書き込みを遮断。
